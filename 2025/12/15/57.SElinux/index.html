前言

这里只是简单介绍SELinux组件以及作用

一、核心概念

SELinux（Security-Enhanced Linux）是 强制访问控制（MAC） 安全机制，由美国国家安全局（NSA）开发，集成在主流 Linux 发行版中。它区别于 Linux 传统的 自主访问控制（DAC），核心特征如下：

  1. 主体（Subject）：发起访问的对象，如进程。
  2. 客体（Object）：被访问的对象，如文件、端口、设备。
  3. 安全上下文（Security Context）：SELinux 赋予主体和客体的唯一标识，格式为 user:role:type:level，其中 type（类型） 是最核心的管控维度。
  4. 策略（Policy）：预定义的规则集，决定主体能否访问客体。常见策略有 targeted（默认，仅管控关键服务）、strict（管控所有进程）、mls（多级安全，用于高安全需求场景）。
  5. 模式（Mode）
    • Enforcing：强制模式，违反策略的操作会被阻止并记录日志。
    • Permissive：宽容模式，违反策略的操作不阻止，但会记录日志（用于调试）。
    • Disabled：关闭模式，SELinux 完全失效。

二、核心作用

  1. 最小权限原则：限制进程仅拥有完成任务所需的最小权限，即使进程被攻陷，攻击者的操作范围也会被严格约束。
  2. 隔离进程与资源：通过安全上下文和策略，隔离不同服务的资源访问。例如，Apache 进程无法随意访问 SSH 相关文件。
  3. 弥补 DAC 缺陷：DAC 基于用户/组权限管控，存在权限过大风险（如 root 进程可访问所有资源）；SELinux 不受用户身份影响，强制拦截违规访问。
  4. 增强系统抗攻击能力：有效防御权限提升、横向渗透等攻击，是服务器（尤其是公网服务器）的重要安全屏障。

四、打开与关闭 SELinux 的问题

1. 保持 SELinux 开启（Enforcing/Permissive）的注意事项

  • 兼容性问题：部分老旧软件或自定义服务可能因 SELinux 策略限制无法正常运行，需手动配置上下文或端口标签。
  • 调试成本增加：服务异常时，需同时排查 DAC 权限和 SELinux 策略，对运维人员要求更高。
  • 日志占用空间：Permissive 模式下会产生大量日志，需定期清理 audit.log。

2. 关闭 SELinux（Disabled）的风险

  • 系统安全大幅降低：失去强制访问控制保护，进程权限不受限制，一旦某服务被攻陷，攻击者可轻易横向渗透或提权。
  • 无法满足合规要求：金融、政务等行业的合规标准（如等保）通常要求开启 SELinux 强制模式。
  • 依赖 SELinux 的功能失效：部分 Linux 安全工具（如 firewalld 高级规则）依赖 SELinux 提供的隔离能力。

注意

从 Disabled 切换回 Enforcing/Permissive 时，需重启系统并可能需要修复文件安全上下文，否则可能导致服务无法启动。
